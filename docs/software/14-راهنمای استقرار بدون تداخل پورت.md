# راهنمای استقرار بدون تداخل پورت

شناسه: FL-SW-14 | نسخه ۱.۰ | وضعیت: نسخه عملیاتی نرم‌افزار با ثبت دستی؛ اتصال صنعتی و پذیرش میدانی در انتظار اجرای پایلوت

## محیط

ویرایش Windows/PowerShell و اجرای پروژه روی VPS با scripts/remote.ps1. Docker محلی و SSH خام برای عملیات پروژه استفاده نشود. hostname و commit کامل ۴۰ نویسه‌ای کنترل می‌شوند. شاخه باید push شده و فایل runner در همان commit موجود باشد.

## ترتیب اجرا

remote.ps1 -Action validate -Sha <commit> سپس برای نخستین backend -Action platform و بعد -Action deploy. gate نصب، lint، build و test باید موفق باشد. platform فقط واحد اختصاصی و virtual host اختصاصی را provision می‌کند؛ Caddy موجود حفظ می‌شود.

## مسیرها

/var/www/fanarlool/releases/<SHA>، current، previous و shared. dist فقط از current سرو می‌شود؛ داده در shared/data و محیط در shared/api.env خارج Git است. RuntimeDirectory در /run/fanarlool سوکت را به گروه www-data می‌دهد.

## تداخل

پورت جدید برای Node باز نمی‌شود. قبل تغییر Nginx syntax و بعد تغییر مسیر HTTPS بررسی شود. فرایندهای دیگر، کانتینر مشترک، rules firewall و شبکه Docker جابه‌جا یا متوقف نشوند. مشکل فضای دیسک با حذف پروژه دیگر حل نشود؛ به مالک گزارش و ظرفیت درخواست شود.

## تحویل حساب

server/admin.mjs فقط از JSON stdin و در نبود مدیر فعال، مدیر نخست را ایجاد می‌کند. رمز را در Git، لاگ، ایمیل یا گزارش ننویسید. پس از provisioning ورود و تغییر رمز توسط صاحب حساب انجام شود. هنوز هیچ حساب پیش‌فرض عمومی ایجاد نشده است.
