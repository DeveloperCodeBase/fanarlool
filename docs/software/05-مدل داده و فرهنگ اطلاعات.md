# مدل داده و فرهنگ اطلاعات

شناسه: FL-SW-05 | نسخه ۲.۰ | تاریخ تدوین: ۱۴۰۵/۰۷/۱۲ | وضعیت: نسخه نخست محصول؛ هسته نرم‌افزاری عملیاتی در محیط تولید و برنامه تکمیل صنعتی

## ذخیره و شناسه

جدول users هویت، نقش، وضعیت و هش رمز؛ sessions هش توکن، زمان و CSRF؛ records شناسه UUID، kind، JSON معتبر، وضعیت، سازنده، نسخه و زمان؛ audit رخداد و عامل؛ login_limits کنترل تلاش ورود را نگهداری می‌کنند. شماره نسخه رکورد از بازنویسی همزمان جلوگیری می‌کند.

## حوزه‌های اصلی

production: بچ، خط، محصول، تاریخ، شیفت، دقیقه برنامه و کارکرد، سیکل ثانیه، کل و سالم. inspection: بچ، قطعه، نمونه، بعد، اسمی، تلرانس، اندازه‌گیری، معیوب، ابزار. maintenance: تجهیز، عنوان، اولویت، موعد، علامت، توقف و نتیجه. energy: کنتور، خط، تاریخ، حامل، قرائت، تناژ، قطعی و شرح.

## داده مرجع

asset: کد، نام، خط، بحرانی بودن، سازنده، فاصله سرویس، آخرین سرویس و منبع قطعه. recipe: قطعه، بازنگری، ماده، قطر مفتول و حلقه، دور فعال، طول آزاد، استاندارد. calibration: ابزار، گواهی، انجام و انقضا، آزمایشگاه و عدم قطعیت. inventory: قلم، بچ/ذوب، واحد، مقدار، حد سفارش، تأمین‌کننده و محل.

## عدم انطباق

ncr شامل بچ، عنوان، شدت، مهار، علت ریشه‌ای، اقدام، مسئول و موعد است. در این نسخه رابطه بچ بر اساس شناسه متنی است و FK به جدول بچ مستقل ندارد. پیش از اتصال ERP باید قرارداد کدگذاری و یکتایی بچ توافق شود.

## کیفیت و واحد

تاریخ ذخیره میلادی استاندارد و نمایش فارسی با timezone تهران؛ درصد OEE از نسبت محاسبه می‌شود. برق kWh، گاز m3 و هوای فشرده m3 مخلوط جمع نمی‌شوند. مقدار اندازه‌گیری و تلرانس باید در واحد یکسان ثبت شوند؛ اعمال تبدیل واحد و توزیع نمونه‌ها توسعه بعدی است.

## ساختار فیزیکی schema نسخه ۲

PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON;
    CREATE TABLE IF NOT EXISTS users(id TEXT PRIMARY KEY, username TEXT NOT NULL UNIQUE COLLATE NOCASE, name TEXT NOT NULL, role TEXT NOT NULL, password TEXT NOT NULL, active INTEGER NOT NULL DEFAULT 1, must_change INTEGER NOT NULL DEFAULT 1, created_at TEXT NOT NULL);
    CREATE TABLE IF NOT EXISTS sessions(token TEXT PRIMARY KEY, user_id TEXT NOT NULL REFERENCES users(id), csrf TEXT NOT NULL, expires INTEGER NOT NULL, last_seen INTEGER NOT NULL);
    CREATE TABLE IF NOT EXISTS records(id TEXT PRIMARY KEY, kind TEXT NOT NULL, data TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'draft', creator TEXT NOT NULL REFERENCES users(id), approver TEXT REFERENCES users(id), version INTEGER NOT NULL DEFAULT 1, created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
    CREATE TABLE IF NOT EXISTS audit(id INTEGER PRIMARY KEY AUTOINCREMENT, actor TEXT, action TEXT NOT NULL, target TEXT, details TEXT NOT NULL, created_at TEXT NOT NULL);
    CREATE TABLE IF NOT EXISTS login_limits(key TEXT PRIMARY KEY, failures INTEGER NOT NULL, until_ms INTEGER NOT NULL);
    CREATE TABLE IF NOT EXISTS user_profiles(user_id TEXT PRIMARY KEY REFERENCES users(id), department TEXT NOT NULL DEFAULT '', job_title TEXT NOT NULL DEFAULT '', email TEXT NOT NULL DEFAULT '', phone TEXT NOT NULL DEFAULT '', preferences TEXT NOT NULL DEFAULT '{}');
    CREATE INDEX IF NOT EXISTS records_kind ON records(kind,created_at);
    CREATE INDEX IF NOT EXISTS sessions_user ON sessions(user_id); PRAGMA user_version=2;
user_profiles افزوده‌شده است و داده schema نسخه ۱ حفظ می‌شود. backup/restore باید نسخه schema را نیز کنترل کند.

## داده مرجع و سیاست اصلاح

کد کارخانه، خط، تجهیز، قطعه، بازنگری، بچ و ذوب با پیشوند واحد تعریف شود. تغییر شناسه بعد از تولید نیازمند mapping تاریخی است. شخص ثبت‌کننده، زمان، منبع و وضعیت برای هر رکورد نگهداری شوند. رکورد ردشده جهت سابقه باقی می‌ماند. اصلاح رکورد approved در محصول نهایی به رکورد correction ارجاع‌دار، دلیل و تأیید مستقل نیاز دارد؛ وضعیت فعلی از ویرایش مستقیم آن جلوگیری می‌کند.

## شجره بچ و دفتر تغییرناپذیر موجودی

شناسه سفارش، بچ تولید و بچ ماده باید قابل ارجاع و کنترل باشند. بچ محصول، زنجیره ماده مصرف‌شده و پرونده کیفیت را به هم متصل می‌کند. حرکت موجودی یک رخداد مقدار/واحد/قلم/بچ ماده با عامل و زمان است؛ اصلاح با حرکت جبرانی مستند انجام می‌شود و حرکت قطعی مستقیم بازنویسی نمی‌شود. مانده از دفتر حرکت محاسبه و برداشت نامعتبر در تراکنش رد می‌شود. تعدیل موجودی و برگشت مصرف باید دلیل و شاهد داشته باشند. سند موجودی عمومی با دفتر حرکت اجرای کارخانه دو مفهوم جدا هستند؛ همسان‌سازی ERP به قرارداد شناسه و واحد مستقل نیاز دارد.

## چرخه وضعیت و معنای آزادسازی

draft/submitted/approved/rejected وضعیت سند ثبت‌شده است. وضعیت سفارش، وضعیت نگهداشت بچ و وضعیت وظیفه، چرخه اجرایی جدا دارند. آزادسازی بچ تصمیم کیفیت در حضور شواهد معتبر و نبود مانع است. نگهداشت یعنی ادامه مصرف یا تحویل باید مطابق دستور مسئول کیفیت محدود شود؛ رابط نرم‌افزار interlock فیزیکی ماشین ندارد. جدول دقیق enumها و گذارها پس از تثبیت قرارداد پیاده‌سازی ثبت می‌شود.

## وضعیت‌های canonical اجرای کارخانه

سفارش: draft، released، cancelled، completed. بچ: queued، running، quality_hold، released، blocked. وظیفه: open، in_progress، verification، closed. جهت حرکت ماده: receipt، issue، return؛ واحد: kg یا piece. وضعیت‌های سند records و وضعیت اجرایی منابع مستقل‌اند. سفارش با recipe و asset تأییدشده مرتبط است؛ محصول باید با part دستور ساخت یکسان باشد. materialLot در بچ، شناسه متنی ماده است؛ سند حرکت مصرف/برگشت با productionLotId رابطه مستقل به بچ محصول دارد. ثبت این برچسب جای گواهی ذوب یا اتصال خودکار ERP نیست.

## قواعد دقیق دفتر حرکت ماده

مانده برای هر ترکیب material/lot/unit مستقل و برابر receipt+return−issue است؛ kg و piece مخلوط نمی‌شوند. issue و return به بچ محصول مربوط‌اند و ماده باید با materialLot همان بچ سازگار باشد. issue بیش از مانده رد می‌شود. return بیش از issue خالص قبلی همان بچ محصول/ماده/بچ ماده/واحد رد می‌شود. حرکت قطعی PATCH نمی‌پذیرد؛ receipt/issue/return جدید با کد یکتا، note و شاهد ثبت می‌شود. return برگشت مصرف ثبت‌شده است و جای تعدیل عمومی یا موجودی آغازین را نمی‌گیرد.
