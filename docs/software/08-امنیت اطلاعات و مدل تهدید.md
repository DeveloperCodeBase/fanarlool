# امنیت اطلاعات و مدل تهدید

شناسه: FL-SW-08 | نسخه ۲.۰ | تاریخ تدوین: ۱۴۰۵/۰۷/۱۱ | وضعیت: نسخه نخست محصول؛ هسته نرم‌افزاری عملیاتی در محیط تولید و برنامه تکمیل صنعتی

## تهدیدهای هدف

سرقت نشست، حدس رمز، CSRF، دسترسی مستقیم خارج نقش، بازنویسی رکورد تأییدشده، فرمول مخرب CSV، نشت دیتابیس از وب و اختلال در سرویس‌های هم‌میزبان. برای هر تهدید کنترل اجرایی و آزمون موردی تعریف شده است.

## کنترل اجرا

scrypt با salt تصادفی؛ توکن نشست تصادفی و ذخیره هش؛ cookie __Host امن HttpOnly/SameSite Strict؛ تطبیق Origin و CSRF؛ محدودیت ورود پس از هشت شکست؛ SQL آماده؛ اعتبارسنجی schema و شماره نسخه؛ داده خارج ریشه dist و فایل DB با مجوز ۶۰۰.

## امنیت میزبان

systemd با NoNewPrivileges، ProtectSystem strict، مسیر نوشتن محدود، AF_UNIX، محدودیت حافظه و tasks اجرا می‌شود. شبکه صنعتی باید از وب عمومی تفکیک شود. دسترسی خروجی cloud برای جمع‌آورنده فقط با allowlist و ثبت وقایع پیشنهاد می‌شود؛ کنترل PLC از وب ممنوع است.

## محدودیت روشن

audit دیتابیس دارای امضای رمزنگاری یا WORM نیست. مدیر OS می‌تواند داده را تغییر دهد. پنتست مستقل، بازیابی خارج سایت، MFA و کنترل ریز سطح خط هنوز باید اجرا شوند. عنوان گواهی یا مهر دیجیتال رسمی بدون زیرساخت اعتماد استفاده نمی‌شود.

## مرجع و اقدام

OWASP Authorization Cheat Sheet و NIST SP 800-82 Rev.3 مبنای طراحی‌اند؛ انطباق یا گواهی با این استانداردها ادعا نشده است. پیش از پایلوت: فهرست دارایی، بازبینی حساب‌ها، رفع هشدارهای تست امنیت و ثبت صاحب هر ریسک.

## تراکنش و مدل تهدید جزئی

T01 دسترسی بیرون نقش: server can و آزمون مستقیم. T02 session stolen: HTTPS، HttpOnly، TTL و خروج. T03 CSRF: Origin و token. T04 race و بازنویسی: UPDATE با نسخه و بررسی changes. T05 ناپیوستگی audit: تغییر و ثبت رویداد در BEGIN IMMEDIATE/COMMIT؛ شکست audit هر دو را rollback می‌کند. T06 revocation race: نشست/نقش پیش از mutation دوباره خوانده می‌شود. T07 CSV injection: نقل‌قول و خنثی کردن شروع فرمول. T08 افشای DB: خارج dist، ۶۰۰ و سوکت خصوصی. T09 دمو: دیتابیس/نشست مستقل و سقف منابع. T10 وابستگی خارجی: lockfile، نسخه runtime و فونت محلی.

## پاسخ رخداد امنیتی

۱. شناسه رخداد، زمان تهران/UTC، نسخه و اثر را ثبت کنید. ۲. فقط حساب یا سرویس پروژه مشکوک را با هویت قطعی محدود کنید؛ سرویس‌های مشترک متوقف نشوند. ۳. لاگ و snapshot را حفظ و hash کنید. ۴. برای session compromise حساب و نشست ابطال و رمز توسط صاحب آن عوض شود. ۵. بازگشت از release شناخته‌شده و تست صحت داده انجام شود. ۶. گزارش ریشه، دامنه اثر، داده افشاشده و اقدام پیشگیرانه تهیه و مسئول کارخانه مطلع شود. ۷. closure به شواهد بازیابی و تأیید مالک وابسته است.
